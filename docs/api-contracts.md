# 📡 PansGPT 2.0 API Contracts

## Chat Recovery

Latest 14 November user correction: no terminal canned answer for missing course evidence. Continue to the answering model with available context/general knowledge/tools; do not fabricate material attribution. An open PDF does not force retrieval for every question: the semantic decider receives availability flags and chooses the route. Course retrieval does not implicitly invoke web search; explicit web routes/tools retain privacy/authorization gates. Database/search outages propagate as actual failures rather than empty search results. See [the recovery decision record](chat-recovery-2026-11-14.md).

Chat recovery amendment (14 November): [contracts and verification](chat-recovery-2026-11-14.md). Stream requests accept optional `retry_message_id` for an unanswered owned user question; edit/regenerate/retry are mutually exclusive. Reuse stored question context and attachments, reject answered/tool-started questions, and reconcile saved responses before manual retry. The `recovery` SSE event is `{state:"retrying", attempt:1..3, retry_after_ms:0..30000}`, separate from model-authored progress. The shared UI retains error codes/retryability but displays controlled public messages and actionable access/usage/validation guidance. Safe operations have bounded backoff; stream/upload/mutation POSTs are never automatically replayed.

14 November chat notice presentation amendment: normal and study chat share compact, dismissible warning/info cards. Offline, composer validation, transcription and conversation-action notices sit above the composer, outside its grid. Mobile uses shorter controlled copy and smaller padding; desktop retains fuller guidance. Failed-response cards remain with their response and retain recovery actions after dismissal. Dismissal never changes sending eligibility or silently retries a request. This is a presentation change; API and retry contracts are unchanged.

## Profile verification recovery

14 November: `GET /api/v1/auth/me` retains its owned profile contract and authorization rules. The browser now uses at most three safe-read attempts with exponential backoff/jitter and bounded Retry-After, 15 seconds per request and 47 seconds total. Account/token changes abort pending work; 401/403 and malformed/foreign successful profiles do not auto-retry. Exhausted transient failures show “Something went wrong” with a round icon-only Retry button; actionable session/access guidance remains separate. Profile PATCH operations are not automatically replayed. See [diagnosis and verification](profile-recovery-2026-11-14.md).

## Core Health Endpoints

- `GET /health/live`: Fast ping response (`{"status": "ok"}`). Used by cron-job.org keep-alive.
- `GET /health/ready`: Readiness probe verifying Supabase, R2, and Redis connectivity.

## Document Ingestion Pipeline

- `POST /api/v1/documents/upload-url`: Generates 15-minute presigned PUT URL to Cloudflare R2.
- `POST /api/v1/documents/process`: Triggers 8-stage ingestion pipeline (PyMuPDF -> Chunk -> Embed -> HNSW).

- `GET /api/v1/library/catalog/{id}/reader`: authorized library metadata, this account's saved page and `chat_session_id: null`. Opening the reader never resumes a conversation automatically; use its owned History endpoint.
- `GET /api/v1/library/catalog/{id}/pdf-url`: existing private 15-minute access to the actual saved PDF.
- `GET /api/v1/library/catalog/{id}/pdf`: authenticated PDF byte transport when the browser cannot read the signed storage URL. Derive the storage key server-side after the same university/status/deletion checks. Full response: `200 application/pdf`; single `Range: bytes=start-end`, open-ended or suffix request: `206` with `Content-Range`. Invalid/multiple/unsatisfiable ranges return `416` with `bytes */size`. Stream 64 KiB chunks, close upstream resources on completion/disconnect, and expose range headers. Every request uses `private, no-store`; clients cannot provide a URL or storage key.
- `PATCH /api/v1/library/catalog/{id}/progress`: `{page}`; bounds checked against the stored document. Returns `LibraryOpenedResponse`; no client-supplied owner or total-pages fields.
- `GET /api/v1/library/catalog/{id}/highlights?offset=0&limit=200`: bounded owned highlights and `next_offset`.
- `POST /api/v1/library/catalog/{id}/highlights`: validated selected text, page, color and normalized rectangles; 201 `ReaderHighlight`.
- `DELETE /api/v1/library/catalog/{id}/highlights/{highlight_id}`: owned/document/university scoped deletion; 204 or 404.
- Existing chat session creation uses `{document_id}`. Streams inherit a bound session's document even if omitted by the client, reject document substitution, accept owned supporting attachments and preserve library scope through retrieval and AI tool execution.

Reader responses use `private, no-store`. Storage, loading and persistence failures remain visible and retryable; live failures never become demo success.

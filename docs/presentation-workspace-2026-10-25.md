# Presentation workspace — 25 October 2026

User approved a Claude-inspired read-only slide workspace, thumbnails/navigation/zoom/download, improved templates and concise completion/progress, using PansGPT's palette. Editing is outside this slice.

Contract before implementation:

- `GET /api/v1/library/artifacts/presentation?key=...` returns a typed presentation preview extracted from the actual owned PPTX in R2: title, width/height in points, slide count, slides with titles/notes and bounded vector/text elements, and rendering warnings. Reuse artifact owner/university authorization, including existing super-admin semantics. No raw R2 URLs or external Office viewers. Private/no-store response; explicit 404/422/503 states.
- Parse in a bounded subprocess after ZIP/XML validation, with source/expanded-byte/slide/element limits and a real process timeout. No persistent derivative files or database changes. Browser renders allowlisted SVG primitives as React elements, never untrusted HTML, external images or JavaScript. Existing unsupported media is reported rather than substituted with fake artwork.
- The semantic router records an optional presentation plan with a nullable requested total slide count. The backend passes this constraint into generation. When explicit document/course/attachment context bypasses the semantic router, a bounded, privacy-gated count resolver runs only after the model actually selects `create_pptx`; it reads selected visible context and the student's request, without a phrase/number-word catalogue. Failure to verify requirements fails visibly. `create_pptx.slides` contains content slides; one cover is generated. `slide_count` includes the cover. Count disagreements fail visibly before upload; do not silently truncate or pad. Legacy direct engine calls without a count remain valid.
- Backend-authored 16:9 cover/content templates use charcoal/green and off-white, consistent margins, typography, page numbers and optional speaker notes. Preview geometry comes from the saved file. Source labels derive from server-verified citations; do not invent references when none were checked.
- Artifact metadata adds real count, titles and source metadata to the existing extensible content field. A concise completion summary identifies the count and topics without repeating slide contents. Dedicated public presentation stages describe planning, layout/validation and readiness; private provider reasoning stays hidden.
- On a newly generated presentation, desktop opens a preview beside chat; selecting an older card reopens it. Mobile uses an accessible modal with Escape/close/focus restoration. Include slide thumbnails, keyboard navigation, fit/zoom, download and recoverable loading/error states. Clear selection and outstanding fetches on account/conversation changes; no artifact storage in localStorage.

Acceptance: a five-slide request produces exactly five slides; one cover, correctly owned download/preview, actual-file slide text and geometry, title/notes/thumbnail navigation, useful progress and concise summary. Verify failed storage, malformed/oversized ZIPs, foreign keys, unsupported media, cancellation, reopening, desktop/mobile layouts and keyboard focus. Hosted rollout remains a separate gate.

25 October completion follow-up contract: `create_pptx` asks the authoring model for a plain-text `overview` (20–600 characters): its natural completion message tailored to the request and actual slide content, with no prescribed opener.

# PDF reader and document study chat — 11 November 2026

User authorized implementation on `feature/pdf-study-workspace`, with `../pansgpt-eli` as a read-only reference. Existing uncommitted settings/support work is outside this change.

## Scope and contracts

- Web route: `/app/library/{document_id}/read`. Open the actual authorized saved PDF with a locally bundled Mozilla PDF.js worker; never use a synthetic replacement on live failures.
- Four layers: virtualized canvas pages, selectable PDF text, normalized highlight overlays, and selection actions. Page navigation, zoom, reading themes, collapsible/resizable desktop chat and full-screen mobile chat.
- `GET /api/v1/library/catalog/{id}/reader`: `{document: LibraryDocument, chat_session_id: string|null}`. Metadata and reading page belong to the authenticated university/account; session is the most recent owned, unarchived conversation bound to this document.
- Existing `GET /catalog/{id}/pdf-url` supplies a private 15-minute PDF URL. Signing/loading errors have explicit retry states; PDF access does not require ingestion/AI success.
- `PATCH /catalog/{id}/progress`: `{page: integer>=1}` → `LibraryOpenedResponse`. Validate against the stored document page count, derive identity server-side, save every 30 seconds and on page hide/exit, restore last saved page. Page-granular resume only; within-page offsets remain pending.
- `GET /catalog/{id}/highlights?offset=0&limit=200`: `{items: ReaderHighlight[], next_offset: number|null}`. Owner/document scoped and bounded; client loads pages until complete.
- `POST /catalog/{id}/highlights`: `{page_number, color, selected_text, rects}` → `ReaderHighlight` (201). Rectangles use normalized 0–1 `{x,y,width,height}`, max 100; text 1–6000 characters. Four colors. `DELETE /catalog/{id}/highlights/{highlight_id}` removes only an owned highlight (204).
- Reuse `study_progress`, `document_highlights`, existing UUIDv7 defaults and RLS. No legacy SQL or records imported; no schema changes required for this slice.
- Create chat sessions with `document_id`; inherit that server-owned scope for every subsequent stream. Reject attempts to substitute another document; force RAG/read tools to that scope and prevent web fallback. Account/university/document changes clear client state and abort old work.
- Selection actions stage a visible, editable quote and page in the shared chat composer. They do not invoke inference until Send. Citations navigate to the source page, with normalized geometry when supplied and honest page-only fallback.

## Acceptance and verification

1. Open a library material inside the app, select text, stage a question, send through FastAPI, and jump from its citation back to the PDF.
2. Navigate/zoom without accumulating offscreen canvases; display loading, inaccessible, expired-link, PDF/password and save failures with retry access.
3. Reopen and restore page; persist/remove highlights without cross-owner or cross-university access.
4. Closing/reopening desktop or mobile chat retains the draft and conversation; keyboard users can resize the divider and operate controls.
5. Synthetic browser fixtures are explicit test/demo data. They establish UI behavior only. Hosted PDF/R2/CORS, real-provider study journeys, native devices and performance budgets remain open until verified.

## Private PDF loading fix — 13 November 2026

- Diagnosis: the reported document's signed storage request returned valid PDF bytes (`206`) without `Access-Control-Allow-Origin` for either localhost or 127.0.0.1. A successful `/pdf-url` response proves signing, not browser access. The configured object-storage key receives `AccessDenied` for bucket CORS administration; no bucket policy was overwritten. [Cloudflare's CORS guidance](https://developers.cloudflare.com/r2/buckets/cors/) confirms that signed URLs still require browser CORS permission.
- Contract: `GET /api/v1/library/catalog/{id}/pdf` delivers authenticated bytes with the existing university/status/deletion scope. Return 200 for full reads, 206 for bounded/open-ended/suffix byte ranges, 416 for invalid/unsatisfiable/multiple ranges. Never accept a caller-supplied URL/key. Stream 64 KiB chunks, validate upstream length/range, close resources, disable caching and expose range response headers.
- Frontend: retain direct R2 access first. On network/transport failures, destroy the failed PDF.js task and retry the same document through the API with its bearer token. Never forward that token to R2. Password/invalid-file errors do not trigger the transport fallback. This preserves virtualized page loading and explicit retry failures.
- Verification: **928 offline API tests passed**, 68 live tests excluded, including **17 new private-PDF transport contracts**. Two focused Chrome journeys passed: blocked-storage/fallback/outage retry and the existing selection/highlight/chat/citation/resume flow. Reader ESLint, TypeScript and production web build passed. The reported real PDF returned 1,024 bytes with 206 and 1,019,723 bytes with 200 through the storage streaming wrapper; PyMuPDF parsed all 7 pages. Database-pooler timeouts prevented a complete hosted authenticated journey. No schema or bucket-policy changes.
- Local runtime recovery: the workspace API listener was accepting connections but timing out on HTTP. Restarted only its verified launcher/children through the normal development launcher. Confirmed `/health/live` and `/api/v1/openapi.json` return 200 and the new PDF route is registered. The API remains running; the browser needs a reload/retry.

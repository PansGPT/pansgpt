# General web routing — 25 October 2026

User-approved scope: allow general questions; verify current facts through backend web search. The user explicitly authorized reusing the legacy Tavily key locally and a retention exception for public searches. This is not verified Tavily ZDR and does not authorize sending uploaded files, full conversations or patient details. Keep the exception off by default and local-only unless separately configured.

Contract before implementation:

- Private semantic decisions select `evidence_source`: `none`, `course`, `web` or `course_and_web`, plus general/biomedical search scope, current-information need and whether the standalone query is public. `requires_rag` in the resolved classification means course retrieval only. General current facts must not run HyDE/vector/FTS/reranking against pharmacy material.
- Supply the actual request timestamp/date and configured IANA timezone (pilot default Africa/Lagos) to the router and answer synthesis. Resolve relative dates semantically, without greeting/sports phrase lists. Stable general questions can reuse a direct answer; current facts require web evidence, even if a model suggests a memorized answer.
- Search before synthesis when the route requires it, preserving tool-disable permissions. Pass only a bounded standalone query to Tavily. Block credential/identifier patterns and require public-query eligibility for the retention exception; pinned private document/attachment turns do not inherit that eligibility. Never set `TAVILY_ZDR_CONFIRMED` for the exception.
- Web results distinguish missing configuration, privacy hold, disabled capability, quota exhaustion, transport/upstream failure and genuinely empty results. Do not turn these states into a course-material absence notice or generate an unverified current answer. Check eligibility before cached results; isolate cache keys by query/scope/freshness and account, with a shorter TTL for current facts. Do not charge search quota when configuration/privacy prevents dispatch; preserve atomic quota reservation before network calls.
- General searches keep the public query intact and use the general index. Biomedical searches retain authority-domain filtering, without rewriting unrelated questions with medical keywords. Basic search only, no paid-depth escalation. Provider citations are actual safe HTTP(S) results, not model-invented URLs.
- General synthesis uses a general assistant prompt grounded in supplied web results. Clinical/course synthesis keeps clinical safeguards and distinguishes external evidence from uploaded material. Existing SSE citations/progress/error contracts remain; raw reasoning stays private. A web answer may prefer the low-latency eligible model cascade without mislabelling it a direct one-completion response.

Acceptance includes semantic paraphrases/follow-ups/date grounding, no RAG for current general facts, correct provider request scopes, no unrelated document citations, actionable unavailable states, empty-search honesty, disabled-tool behavior, privacy before cache/quota, cache isolation/expiry and retained clinical grounding. Live verification uses public synthetic queries only; no student history/files or patient details.

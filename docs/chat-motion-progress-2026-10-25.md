# Chat motion and public progress

Approved scope: transitions.dev Streaming text, Thinking states and Matrix dot loader, using PansGPT theme colors. The model writes the thinking-status wording for the actual task; no timed catalogue of invented activities and no private reasoning display.

Contract: `public_progress` SSE carries `{code, label, source:"model"}`. Codes identify backend-authoritative activity phases; labels are bounded, plain text composed in the existing semantic decision or an actual tool call. A planned label is emitted only when its phase actually runs. Model labels cannot authorize tools, retrieval, providers or completion. The router's direct answer remains its single completion. Explicit-context bypasses keep their existing behavior; no extra inference is added solely for status copy. A generic waiting indicator is used until model-authored progress is available. Existing fixed backend stage labels remain compatible activity-history records, separate from the model-authored thinking line.

Persistence: save validated public updates under `tool_calls.public_progress` in the existing owned message JSON, expose them as a typed `public_progress` history field, and parse them separately from legacy `thinking_text`. Existing raw reasoning remains filtered. No schema migration or provider/privacy change.

Motion: animate actual status changes and newly arrived prose only. Preserve assistant-ui Markdown, code, equations, tables, copy behavior, scroll position and terminal errors. Do not replay saved answers or queue words behind model delivery. Use the original namespaced recipe CSS, semantic color overrides, reduced-motion guards and no additional motion dependency. Stop the waiting animation on answer text, cancellation or error; actual running tools may resume a progress indicator.

Acceptance: offline backend tests cover source validation, actual-phase gating, private-reasoning rejection and saved/reloaded updates. Client contracts cover malformed events/history, terminal states and deduplication. Browser checks cover desktop/mobile status swaps, streamed formatted content, saved answers and reduced motion. Hosted/provider/native gates remain open.

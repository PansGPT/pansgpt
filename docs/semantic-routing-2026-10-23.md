# Semantic route-or-answer — 23 October 2026

26 October follow-up: the private decision now includes semantic `response_mode=brief|extended`. Extended deliverables use the existing streamed generator even when no evidence or tools are needed; brief answers still reuse one completion. A 120-word/1200-character direct-output bound prevents an oversized router answer from bypassing generation. Neither input length nor phrase matching selects the route. Missing mode remains compatible with older decisions. [Exact essay diagnosis and verification](chat-motion-repair-2026-10-26.md).

The user confirmed that PansGPT should interpret intent and context rather than require developers to anticipate every greeting or simple question. This replaces the regex classifier, which routed “hello chat” into retrieval and returned a course-material absence notice before reaching an answer model.

- FastAPI calls a bounded semantic router with the current message and up to six selected user/assistant messages, capped at 6,000 history characters. System messages, tool arguments and private reasoning are excluded. The model chooses a direct answer, a clarification or a grounded handoff; message length and phrase matches do not choose the route.
- Latest outage correction: routing unavailability now returns `AI_ROUTING_UNAVAILABLE`, refunds/releases the run and skips retrieval; it no longer guesses that the request needs RAG. See [outage correction](semantic-routing-outages-2026-10-23.md).
- Eligible provider order: configured Groq primary/secondary, Google primary/secondary, OpenRouter fast/fallback. Duplicate attempts are removed; per-model circuits, provider privacy, a shared 12s budget and an 8s attempt deadline apply. Connection failures temporarily skip the provider for 30s; HTTP connection setup is capped at 4s. OpenRouter retains the ZDR/data-collection constraints; Google's existing retention exception is unchanged.
- The private `SemanticDecision` schema validates every response. Supported Groq models use strict JSON decoding; other configured models use JSON mode or prompt-based JSON plus the same local validation. This accommodates the provider capabilities described in [Groq's structured-output documentation](https://console.groq.com/docs/structured-outputs). The configured GPT-OSS router uses low reasoning effort; the supported Qwen router disables reasoning for this small decision.
- Direct answers and clarification questions are reused from that same completion. They pass output/privacy filters before public SSE emission and use the existing owner-scoped branch persistence, credit settlement and run release. Short replies are delivered after JSON validation, without a second answer-generation call or artificial token animation. Deeper work retains the agentic engine and streamed answers.
- Clinical-risk or clinical/course-evidence decisions cannot become direct replies. Artifact intents require tool handoff even when the content is already in history; the router must not substitute a slide outline for a downloadable presentation. Optional standalone retrieval queries resolve contextual follow-ups. Explicit pinned document, course and attachment requests retain the existing grounded-scope contract. User retrieval/tool disables remain authoritative.
- Invalid JSON, inconsistent direct answers, low-confidence answer decisions, timeouts and unavailable providers never expose the speculative answer. Eligible models are tried within the deadline, then the request ends with a retryable service error; only a validated decision or explicit document context starts the grounded workflow. Ambiguity can instead produce one clarification question. Cancellation propagates.
- Public progress remains allowlisted. Router JSON, confidence and private deliberations never become chat content. Logs identify the route, provider/model and latency; provider-reported usage is logged when supplied. Routing calls also schedule the existing owner/university telemetry with explicitly estimated token counts, including handoffs. One user chat credit still follows the existing successful-turn settlement rules.

Defaults in both environment templates: `INTENT_ROUTER_TOTAL_TIMEOUT_S=12`, `INTENT_ROUTER_ATTEMPT_TIMEOUT_S=8`, `INTENT_ROUTER_MAX_TOKENS=768`, `CHAT_RETRIEVAL_TIMEOUT_S=25`. No new provider, dependency, public client DTO, migration or database deployment was introduced.

# PDF reading flow — 14 November 2026

Continues `feature/pdf-study-workspace`. This follow-up supersedes automatic conversation restoration, staged text actions, visible page/reference chips and reading controls inside the Page dialog in the earlier reader records. Existing document access, upload provenance and backend inference boundaries remain authoritative.

## Behavior and acceptance

- Opening `/app/library/{id}/read` restores the saved reading page and starts an empty study chat. `ReaderResponse.chat_session_id` remains in the compatibility contract but is always null. History is the explicit way to resume a saved owned conversation; closing/reopening chat during the same reader visit preserves the current conversation and draft.
- Explain, Define, Example, Summarize, Answer and Memory Aid send the action instruction and selected text directly. Wait for first-chat consent and an existing run to finish. Preserve unfinished composer text and attachments; do not include them implicitly in the selection action. Copy remains local. Snips remain editable attachments before Send.
- Remove selected-page wording from selection prompts, crop previews and snip filenames. Hide source chips in study chat and ask the bound-chat model to avoid page tags, citation markers and reference sections unless asked. Preserve backend source metadata and distinguish filenames when discussing conflicting supporting evidence. Normal chat source displays are unchanged.
- Go to page is a compact dialog with a number, total, Go and close. No reading controls. Desktop zoom/theme controls remain in its bottom toolbar.
- Mobile keeps the dock flush to the sides/bottom with square bottom corners and a lighter semantic surface. Downward scrolling hides header/dock; upward scrolling or tapping the page reveals them. Transform only the bars: preserve viewport dimensions, page width and scroll anchors. Do not hide controls during selection, snipping, dialogs or chat. Hidden controls are inert; respect reduced motion.
- Reader loading and errors fill the page without the app sidebar/topbar. Hide the reader's own header, toolbar and study panel until PDF bytes are usable, and on PDF failure. Retry and Back to library remain available.

## Private browser PDF copies

`lib/reader-pdf-cache.ts` uses CacheStorage rather than localStorage strings. A successful, fresh reader metadata/access request is required before reading cached bytes. Keys include account, university, document and `updated_at` revision. Store complete PDF bytes only after signature, PDF.js parsing and first-page validation; never store signed storage URLs, bearer tokens or chat content.

- At most **50 MiB per file**, **12 files / 256 MiB total**, **30 days**. Evict oldest stored copies first and remove superseded revisions. Browser eviction/quota restrictions can remove or prevent copies.
- Small PDFs use a bounded full download; oversized responses stop and retain the existing PDF.js range transport. Storage transport failure retries through the authenticated API without sending bearer tokens to R2.
- Serialize writes and invalidate pending writes during cleanup. Logout clears private copies; account/university changes remove other accounts' copies. An explicit document 403/404 discards that document's copies. An access outage never falls back to cached content.
- Corrupt/expired copies are discarded and reloaded. Unavailable disk storage leaves network reading functional.

This avoids repeated PDF downloads after an access check. It does not implement offline app navigation or offline authorization; native storage, Serwist/PWA integration and hosted/device performance remain separate work.

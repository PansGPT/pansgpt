Contracts before implementation:

- New-chat UI creation sends `{}` to `POST /api/v1/ai/chat/sessions`, leaving naming pending. An explicitly supplied title is manual. Shared create/update/search/recovery responses remain backend-authoritative; rename can deliberately choose “New Chat” without enabling AI overwrite.
- Session metadata adds `title_source: pending|generated|manual` and nullable `last_message_at`. Manual names are authoritative, including a manual name of “New Chat”. Existing nondefault titles are preserved as manual. Activity ordering uses message timestamps, never rename/pin timestamps. AI titles are generated after a successfully saved answer, asynchronously with privacy-gated bounded provider fallback. A model returns null for greetings/no clear topic; there is no greeting phrase list. Failures retain New chat and can retry after the next successful exchange.
- `GET /api/v1/ai/chat/search?q=...&include_archived=false&limit=20&offset=0` returns `{results:[{session_id,title,message_id,snippet,is_archived,last_message_at}],next_offset}`. Query length 2–200; page size 1–50. PostgreSQL full-text title/message search plus literal substring fallback; selected-branch user/assistant messages only. Results are owner/university scoped, exclude deleted chats, and carry plain text snippets rather than HTML. Search covers server history, not just loaded sidebar rows. Navigation targets the matched message; indexed history supports pagination.
- `GET /api/v1/ai/chat/trash?limit=50&offset=0` returns `{sessions:[metadata + deleted_at],next_offset}` for the authenticated owner/university, only within the 30-day recovery window. `POST /api/v1/ai/chat/sessions/{id}/restore` restores that owner's recoverable session and returns metadata. Expired/foreign sessions return 404. Restore retains archived/pinned state. No permanent-delete control is introduced.
- Rename/pin/archive/delete remain server-authorized. Archive and delete offer a short Undo notice after server success; failure remains visible and retryable. Delete uses a compact confirmation explaining 30-day recovery. Archive hides pinned chats too; restoring preserves the pin. Pinned and Recent are separate sidebar groups. Rename/delete use accessible centred dialogs. Archived/deleted library remains reachable from the sidebar archive control.
- Thirty-day purge retains attachment cleanup through the existing durable R2 queue. A versioned migration adds cleanup for generated artifact keys owned by the purged session's user, protecting keys still referenced by another conversation. This does not certify a full cross-feature DSAR workflow.
- Shared DTOs live in `packages/types`, with aligned Pydantic and authorization/contract tests. Versioned migrations are mirrored and executed only via the Supabase CLI. No manual SQL Editor or credentials in logs. Live migration/catalog/journey checks and local UI fixtures are recorded separately; local mocks do not certify hosted integration.

**PansGPT phases 0–7 implementation audit — 20 October 2026**

**Verdict:** The foundations are substantially implemented, but phases 0–7 cannot be certified as fully aligned, correct, or verified. The roadmap overstates completion. There are security defects, incomplete live provider integrations, ingestion recovery defects, and gaps in the quality gates. Several requirements in the plan also need revision.

Audited revision: `b3ee1f4`. Sources: `AGENTS.md`, `docs/build_roadmap.md`, relevant implementation-plan sections, application code, migrations, deployment configuration, and tests. Scope includes phase-7 authentication code in web/mobile/desktop, but does not certify the later product UI. Implementation-plan historical inventory and checkmarks indicating approved design were not treated as proof of implementation.

This audit did not change application code, deploy services, apply migrations, or call live AI providers. Temporary offline probes were removed after execution. The Next.js build's generated change to `next-env.d.ts` was restored.

**Findings, ordered by impact**

1. **Critical — Authorization falls back to user-editable metadata. Reproduced.**

   [dependencies.py:223](../apps/api/app/core/dependencies.py#L223) initializes roles and university from JWT `user_metadata`. If the profile is absent, the connection is unavailable, or lookup fails, it returns and caches those values. An offline probe supplied `roles=["super_admin"]` with no database profile and received super-admin context. A signed JWT does not make user-editable metadata authoritative. Supabase explicitly [warns against using this metadata for authorization](https://supabase.com/docs/guides/auth/users).

   Fix: resolve privileges and tenancy from server-controlled records. A missing profile should have a narrowly defined onboarding state; an unavailable authorization store should return 503. Never grant elevated roles from metadata. Invalidate authoritative role caches on role/account changes and test failure paths with real student metadata.

2. **Critical — Profile RLS allows privileged self-mutation and excessive profile reads. Confirmed in migration source; hosted grants not tested.**

   [users_update_self](../supabase/migrations/20260906090008_row_level_security.sql#L74) checks only `id=auth.uid()`, leaving `roles`, `university_id`, `subscription_tier`, and other sensitive columns unrestricted by that policy. The later [users_insert_self](../supabase/migrations/20260911010001_phase4_database_foundation_complete.sql#L422) likewise checks only identity. No later migration revokes these column capabilities. Under standard Supabase Data API grants, a student can change their own roles. `users_select_self` also permits every same-university user to read peer profiles without requiring an admin role.

   Fix: follow the plan's FastAPI-only data boundary and revoke direct profile writes from client roles, or explicitly allowlist safe editable columns while guarding protected columns. Restrict peer-profile access by role and return minimal public profile views. Add disposable-database tests for self-promotion, university changes, subscription changes, and peer PII reads. Browser route guards do not secure the Data API.

3. **High — JWT caching extends acceptance beyond token expiry; claim validation is incomplete. Reproduced.**

   [dependencies.py:311](../apps/api/app/core/dependencies.py#L311) caches verified tokens for 300 seconds without clamping to `exp`. A token first verified ten seconds before expiry remained accepted at simulated time twenty seconds later. Another probe accepted a signed token without `exp` and with an unrelated issuer/audience. `verify_aud` is disabled; issuer and required claims are not configured. The gateway fallback caches reconstructed claims without retaining token expiry.

   Fix: prefer cached JWKS keys over cached successful authorization. If retaining token cache entries, bound them by `min(exp, now+TTL)` and validate expiry on every request. Require `exp`, `sub`, and the project's expected issuer/audience; explicitly permit only supported signing algorithms. Add before/after-expiry tests for the same token, not just tokens already expired at first use. Bound cache sizes and avoid blocking gateway/JWKS network work on the async request loop.

4. **High — Privileged credit RPC lacks a caller boundary. Confirmed in migration source; live reachability unverified.**

   [deduct_user_credits](../supabase/migrations/20260911010001_phase4_database_foundation_complete.sql#L530) is `SECURITY DEFINER`, accepts any `p_user_id`, and has no `auth.uid()` or role check, fixed search path, or corresponding execute revocation in the tracked migrations. With normal function grants this permits direct deduction from another user's balance. The web-search increment RPC is explicitly granted to `authenticated` while accepting arbitrary user IDs too.

   Fix: revoke execute from public/anon/authenticated for server-only mutations; grant only the dedicated server role. Fix the definer search path and schema-qualify objects. If a client-callable operation is required, derive identity internally. Test direct RPC access as anon/student and verify grants after migration replay.

5. **High — Google's primary tool integration omits tool definitions. Reproduced.**

   [_call_gemma_turn](../apps/api/app/engines/llm.py#L209) receives `tools`, but its `GenerateContentConfig` includes only the automatic-calling setting. It never passes the declarations to Google. The audit captured `config.tools is None` with tools supplied. Consequently the intended native tool-selection path has no declared tools. Both Google paths also omit the configured output token ceiling. The tools-enabled response is buffered and then replayed word by word.

   Fix: convert the common registry into Google's `Tool(function_declarations=...)` representation, preserve native content/function-response roles, supply the output budget, and stream text plus tool-call events. The [official Gemma integration](https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api) demonstrates passing declarations in the generation config. Test captured SDK requests and complete tool-result round trips, rather than mocking the entire provider adapter.

6. **High — Re-embedding deletes retrieval content but does not queue replacement work. Reproduced.**

   [reembed_document](../apps/api/app/routers/library.py#L796) invokes `prepare_document_reembed`, returns “Document re-embedding queued,” and never calls the queue producer. The [SQL function](../supabase/migrations/20261014210000_prepare_document_reembed_clear_images.sql#L6) deletes chunks/elements/segments/pages/images and sets the document pending. No periodic database-to-ARQ dispatcher exists. The audit confirmed no enqueue call while the response claimed success.

   Fix: create a durable ingestion request in the same database transaction and dispatch it through an outbox, with an idempotent job ID. Preserve the previous ingestion version until the replacement succeeds. Return queued only when work is durably scheduled; report dispatch failure accurately.

7. **High — Worker retry timing conflicts with the claim lock. Confirmed by control-flow review.**

   [ingest_document_job](../apps/api/workers/tasks.py#L179) retries transient exceptions after 30/60 seconds, but leaves `embedding_status='processing'` and a recent heartbeat. Its next attempt uses a new worker ID. The [claim RPC](../supabase/migrations/20261019000000_require_approval_before_ingestion.sql#L2) permits pending jobs or processing jobs whose heartbeat is older than ten minutes. The retry therefore fails its claim and returns `False`, ending the ARQ job while the document can remain processing.

   Fix: implement an explicit lease/state machine. On retryable failure, conditionally reset to pending using the current lock owner, or retain a stable lease identity across attempts. Distinguish lock contention from terminal completion, and add a reconciler for abandoned jobs. Every state/progress/final write should check lock ownership. Test first-attempt failure followed by an actual second claim.

8. **High — The claimed ZDR guarantee is not implemented and conflicts with free-tier assumptions. Code review plus official-source verification.**

   [llm.py](../apps/api/app/engines/llm.py#L233) sends `X-Data-Retention: false`, but this does not establish a provider contract or documented ZDR enforcement. OpenRouter payloads omit provider privacy preferences. Its [documented per-request control](https://openrouter.ai/docs/guides/features/zdr) is `provider.zdr=true`; Groq exposes [organization Data Controls](https://console.groq.com/docs/your-data). Google's [unpaid-service terms](https://ai.google.dev/gemini-api/terms?hl=en) permit specified use of submitted content and responses, including improvement of products, with regional/account exceptions. Embeddings, OCR, STT, and query expansion need the same review as chat. Actual account settings were not inspected.

   Fix the plan before claiming guaranteed ZDR: record each provider's contractual retention/training policy, enforce documented routing options, verify account controls, and fail closed if a privacy-required route is unavailable. “Not used for training” and “not retained” are separate requirements. Strict $0 plus every listed provider plus universal ZDR cannot simply be asserted from a header.

9. **High — Deployment blueprint is not a valid verified $0 worker topology. Confirmed configuration defects.**

   [render.yaml:101](../render.yaml#L101) and its production counterpart declare background workers with `plan: free`. Render's [current plan table](https://render.com/docs/compute-plans) provides free compute for web services, not background workers. Both worker env lists omit `SUPABASE_ANON_KEY`, which hosted `Settings` requires. Both web services override the configured OpenRouter safety net with `google/gemma-2-27b-it`, without `:free`. The separate picture queue has an explicitly manual burst worker and no hosted service definition.

   Fix: document one deployable topology that meets the actual budget: an explicitly operator-run ingestion/picture worker for a $0 pilot, or a budgeted hosted worker. Do not describe operator-run jobs as always available. Align shared worker/API settings and fallback IDs through a common environment group and validate blueprint/settings together. Any co-location proposal needs resource and failure-isolation measurements first.

10. **High — The web lint gate passes while its application files are ignored. Reproduced.**

    The [root ESLint config](../.eslintrc.json) ignores `apps/**`. The web config does not terminate inheritance with its own root boundary. [The web script](../apps/web/package.json#L9) targets only `app` and suppresses unmatched patterns. Workspace lint returned success. An expanded invocation without that suppression failed with “all files matching the glob pattern app are ignored”; effective ignore configuration included `apps/**`. It also excludes `lib`, `components`, and other runtime files. Explicit `any` remains in auth code despite the non-negotiable rule.

    Fix: establish a valid app ESLint root/config, lint all maintained runtime directories, enable `@typescript-eslint/no-explicit-any`, and remove suppression that hides an empty target. Align shared Next ESLint tooling with the actual Next version. CI should fail if a known source fixture is not linted. Strict `tsc` permits explicit `any` and cannot enforce this rule itself.

11. **High — Database connection context manager mishandles exceptions from its caller. Reproduced.**

    [get_db_connection](../apps/api/app/core/database.py#L54) catches exceptions across its `yield`. A query/application exception can trigger a new connection or a second yield rather than propagating. The audit raised an HTTP 403 inside the context and received `RuntimeError: generator didn't stop after athrow()`. This masks the cause and can replace intended client errors with 500s.

    Fix: catch only connection acquisition failures before yielding; yield exactly once; release in `finally`; let caller exceptions propagate. Never re-run caller work on a new connection implicitly. Adopt the same connection/pool lifecycle in workers and library routes, which still create many per-call connections.

12. **High — Successful auth responses can represent failed or nonexistent persistence. Reproduced for onboarding; invitation creation confirmed by review.**

    [complete_onboarding](../apps/api/app/routers/auth.py#L162) logs persistence failures, populates the profile cache, and returns `is_onboarded=True`. An offline probe with no database connection and an arbitrary institution received success. [Invitation creation](../apps/api/app/routers/admin.py#L117) similarly catches insert errors and can return a created link/send email for a row that does not exist.

    Fix: persist and verify the authoritative state first; return 503 on storage failure. Populate cache after commit. Queue invitation email from an outbox only after the invite exists. Keep explicit local demo behavior separate from hosted behavior.

13. **Medium — Browser fallbacks bypass the planned backend boundary. Confirmed in source.**

    [auth-context.tsx:61](../apps/web/lib/auth-context.tsx#L61) reads `users` through Supabase when the API fails. [onboarding/page.tsx:162](../apps/web/app/onboarding/page.tsx#L162) writes `users` directly after unsuccessful API onboarding; its university list has a direct fallback too. This contradicts implementation-plan section 3.9 and bypasses API validation, cache invalidation, and centralized authorization.

    Fix: retain Supabase Auth calls for sessions/sign-in, route application data through FastAPI, and show a retryable unavailable state on API failure. Coordinate removal with profile-grant hardening. This is a data-boundary deviation; AI calls themselves are routed through the API in the reviewed clients.

14. **Medium — Environment validation is incomplete or disconnected. Reproduced for hosted API settings.**

    [apps/web/env.ts](../apps/web/env.ts) defines a validator but is not imported by the application/configuration; callers read `process.env` directly. It retains localhost defaults for required hosted URLs. CI sets `API_BASE_URL`, while client code expects `NEXT_PUBLIC_API_URL`. Hosted API validation checks only four database/auth fields, allowing missing inference, embeddings, storage, and queue settings. Mobile also defaults to a specific hosted project and placeholder key.

    Fix: execute validation at startup/build, consume typed config consistently, and validate requirements by enabled capability. Require inference/embedding/storage/queue credentials when those engines are enabled. Do not require future payment secrets before payments exist, or a legacy HS256 secret when JWKS is authoritative. The plan's flat “all secrets required” examples should be revised to avoid both under-validation and unnecessary coupling.

15. **Medium — Text chunk size/overlap and semantic sectioning are overstated. Reproduced for size; sectioning reviewed.**

    [split_text_recursive](../apps/api/app/engines/chunker.py#L53) splits paragraphs and sentences but never implements its documented word/token fallback. A long unpunctuated paragraph remained far above a configured 64-token maximum. Overlap keeps a whole prior piece rather than a bounded token suffix. [Sectioning](../apps/api/app/engines/ingestion.py#L152) uses the first line's capitalization, not the checked-off LLM topic-shift detection; the inherited-title condition cannot normally follow the active explicit-segment transition. Segment end pages also initially extend to the document end.

    Fix: enforce a hard text token limit with a token-slice fallback and bounded overlap; define an explicit large-table/diagram policy. Use heading/font/layout structure before optional model assistance; benchmark whether LLM sectioning is worth its quota. Close segment boundaries at the next heading. Record the chosen chunk defaults consistently: current 512/64 differs from AGENTS' 500–1000/10% guidance.

16. **Medium — Automatic web fallback bypasses per-user quotas; quota reservation is not atomic. Reproduced for identity omission.**

    [rag.py:509](../apps/api/app/engines/rag.py#L509) invokes search without user identity/role. The audit captured this omission. [search](../apps/api/app/engines/web_search.py) enforces/increments user quota only when identity is present. For identified requests, a separate read/check before increment also allows concurrent requests past the limit. In-memory fallback does not coordinate the two production API processes.

    Fix: pass an authoritative request context through initial RAG and every tool route. Atomically reserve quota with a Redis script or transactional database operation before a provider request; reconcile failures according to a documented charging rule. Use shared cache/quota storage and a provider-wide budget as well as user limits.

17. **Medium — Fallback, registry, and streaming guarantees are incomplete. Confirmed in source.**

    [_call_openrouter](../apps/api/app/engines/llm.py#L550) uses a non-streaming response, drops assistant tool calls/tool messages, has no tool schema, and hardcodes a 1500-token ceiling. `_openrouter_turn` emits the complete answer as one chunk. The configured Groq secondary and OpenRouter fast models are not actually traversed by the chat fallback loop. There is sequential failover, but no persistent open/half-open circuit state. `ALL_TOOL_DEFINITIONS` is static; no runtime query of `public.ai_skills` exists. Seeded dosage/interaction skills are not exposed as executable handlers.

    Fix: define a provider adapter contract for text deltas, tool deltas, usage, deadlines, and privacy. Test every candidate/capability. Implement real provider health/cooldown state and explicit degraded-capability behavior. Drive active skills from the registry mapped to allowlisted typed handlers; never execute arbitrary database-stored Python. Either implement the seeded clinical tools with validated inputs and authoritative data, or mark them unavailable.

18. **Medium — Readiness, keep-alive, and worker completion do not prove the expected service health. Confirmed in source.**

    [readiness_check](../apps/api/app/main.py#L94) probes database/Redis but bases readiness on database alone; it does not check R2. An unconfigured database can count as ready. The [keep-alive workflow](../.github/workflows/keep_alive.yml#L16) pings only one URL and prints the status without failing on non-2xx; it is not proof of web monitoring or alerts. Mixed documents can be marked completed while images remain pending, and image-queue dispatch failures are logged without a durable retry path.

    Fix: distinguish liveness from capability readiness. Define whether chat, uploads, ingestion, and vision are required or degraded independently. Use cached lightweight probes, make external checks fail visibly, and record worker queue age/failures. Treat two-stage ingestion as a documented state model with visible partial/vision-pending state and a recovery path. Test manual picture-worker operation as an operational dependency.

19. **Medium — Database governance and generated contracts have drifted. Confirmed by comparison.**

    Nine SQL files in `supabase/migrations` are absent from `packages/database/migrations`; the mirrored `20260906090008_row_level_security.sql` differs. The initial 28 tables enable RLS in a later migration rather than at creation. The migrations declare 47 tables; [TypeScript definitions](../packages/types/src/supabase.ts) cover 45, omitting `document_images` and `web_search_usage`. The declared credit RPC takes `p_amount` and returns boolean, while SQL takes `p_action_key` and returns an integer. Hybrid-search args/returns are also inconsistent. `Relationships` metadata is absent. The generator redirects directly to its destination, so a failed generation can truncate the existing file.

    Fix: make Supabase's directory the authoritative executable history and automatically verify the required mirror. Regenerate types from a freshly migrated disposable database and fail CI on drift; generate to a temporary file before atomic replacement. Enable RLS in each future table-creation migration. Repair deployed history through new versioned migrations; do not silently rewrite already-applied SQL.

20. **Medium — Important phase-4/7 lifecycle work remains incomplete. Confirmed in source.**

    `purge_soft_deleted_records()` exists but no daily schedule/worker calls it; it omits soft-deleted documents. Hard-deleting `public.users` alone also does not delete its parent `auth.users` record. Invitation creation/validation exists, but there is no redemption endpoint/transaction granting roles and incrementing use count, and web signup ignores the invite token. Upload creation omits `uploaded_by`, losing submitter provenance. Desktop stores arbitrary callback tokens without a tracked OAuth attempt/state/PKCE exchange; mobile/desktop have no demonstrated full refresh/logout integration journey.

    Fix: implement observable retention jobs with database/auth/R2 cleanup responsibilities, preserving referential integrity. Add authenticated atomic invitation redemption with expiry/use limits, idempotent redemption, and audit records. Set upload ownership from the verified actor. Treat native-client auth as scaffolding until browser launch, callback binding, secure persistence, refresh, and logout are tested end to end.

21. **Medium — Retrieval differs from its documented scoping/search/citation contract. Confirmed in source; SQL performance unmeasured.**

    The latest [hybrid RPC](../supabase/migrations/20261010030000_embedding_1536.sql#L42) accepts but does not use `filter_levels`, uses `plainto_tsquery` instead of the specified web-search syntax, and filters trigram scores via a raw similarity function rather than an indexable trigram operator. The vector halfvec(1536) index and query casts are correctly aligned. When a supplied course code resolves no documents, the dense path can retain a null document filter and widen to the institution; sibling expansion checks document but not the same segment. Citations reuse stored element/page geometry; runtime extraction of exact quote-level coordinates is not demonstrated by this path.

    Fix: specify and enforce tenant/course/cohort/document filters consistently, returning an empty result for an empty requested scope. Bound expansion by segment. Use the appropriate trigram operator/index and `EXPLAIN (ANALYZE, BUFFERS)` on realistic data before declaring indexed performance. Require exact source-span evidence for exact highlighting. Keep the already implemented explicit external-source labeling and honest no-source responses.

22. **Medium — CI misses integration and contract gaps that passing mocks cannot reveal. Confirmed in workflow/test configuration.**

    [ci.yml](../.github/workflows/ci.yml) runs offline pytest, typecheck, lint, build, and secret scans, but no local Supabase migration reset/seed, SQL grants/RLS tests, generated-type diff, or web SSE test command. Python Ruff selection does not enforce complete annotations or Pydantic strictness; the API models use default coercion rather than a shared strict schema policy. Existing auth tests also synthesize privilege-bearing `user_metadata`, reinforcing the unsafe fallback. Branch-protection enforcement itself was not inspected.

    Fix: retain fast offline tests, then add a disposable migrated Supabase integration job covering grants, policies, RPCs, retries, and contracts. Run the existing web tests in CI, format checks, and valid complete lint targets. Add typed strict input schemas with deliberate compatibility exceptions and annotation enforcement. Keep live-provider smoke tests explicit and budgeted; require actual staging evidence before marking an operational gate verified.

**Additional defects and specification drift**

- `GROQ_VISION_MODEL` defaults to `llama-3.2-11b-vision-preview`, [shut down on 14 April 2025](https://console.groq.com/docs/deprecations). Select a currently supported compatible vision model and test its adapter. `qwen/qwen3.8-27b` is listed in [Groq's current model documentation](https://console.groq.com/docs/models), so its difference from the plan's 3.6 identifier is documentation drift, not evidence of an invalid model.
- Next.js is 16.3.8, despite Next.js 15 descriptions. `.python-version`, Docker, and CI correctly use Python 3.12, while old README/checklist text still says 3.11. `.nvmrc` and `.node-version` pin Node 20.18.0 while CI/web parser verification use Node 22. Standardize the supported local runtime instead of downgrading working upgrades for textual conformity.
- Compose starts plain pgvector PostgreSQL 16 on 5432 with `postgrespassword`; Supabase CLI specifies PostgreSQL 17 on 54322 and provides auth schemas/roles that plain Postgres lacks. The API's no-env development DSN points at 5432 with password `postgres`. Document and validate one default local topology. A Compose file's presence does not prove the Supabase local gate passed.
- The review found no Supabase Realtime publication setup for document progress. A realtime checkbox should require publication/subscription evidence or be changed to match polling.
- The PDF export skill creates a single page and ignores `insert_textbox` overflow. Long generated notes can yield incomplete PDFs. Implement pagination and verify extracted output text against the intended content.
- Outgoing streaming sanitization runs on individual chunks. Patterns split across chunk boundaries can escape before final whole-answer checks. Use a bounded streaming buffer and test cross-chunk leakage; keep sensitive internal credentials out of prompts entirely.
- SSE keep-alive and disconnect checks run only when an upstream model event arrives. They are not independent timers during a quiet provider/tool call. Use a concurrently managed producer/heartbeat queue with cancellation propagation and test long silent periods.
- Credits are now deducted before generation, a useful improvement over the plan's background-only charge. However, deduction precedes prompt-policy rejection and there is no demonstrated refund/idempotency lifecycle for provider failure. The ledger is a single-account balance journal, despite its “double-entry” label. Do not claim true double-entry accounting without balanced entries/accounts.

**Recommended changes to the plan itself**

1. Keep backend-owned inference, versioned migrations, tenant isolation, UUIDv7 application records, the 1536d storage/index contract, and offline unit-test isolation. These are sound directions and substantially present.
2. Replace background credit deduction with atomic reservation, idempotent settlement, and release/refund on the defined failure paths. Retain synchronous authorization before inference; move nonessential telemetry/title work off the token path with reliable shutdown behavior.
3. Define a deployable $0 pilot separately from production availability. Operator-run ingestion is a valid budget choice only with explicit availability limits and runbooks. Record provider privacy eligibility independently of price.
4. Revise “all client API keys are secrets.” A distributed mobile/desktop binary or browser cannot safely hold an application-wide secret. Use JWTs for user authorization, treat client IDs as labels, and reserve confidential API keys for trusted server-to-server callers. A web BFF is an option only if the plan also chooses a server-managed session model.
5. Choose a coherent browser token model. The current Supabase browser client uses JS-accessible auth state, so the blanket HttpOnly storage claim is not established. Either document the SSR/browser model accurately or implement a BFF with HttpOnly session cookies and corresponding CSRF controls.
6. Use durable ingestion generations and an outbox instead of deleting the active index before replacement. Make retries, lock ownership, queue delivery, partial vision status, and stalled-job reconciliation explicit contracts.
7. Prefer deterministic structure extraction before LLM topic detection. Spend optional model quota only when measured retrieval/learning quality justifies it; evaluate chunk size on a pharmacy retrieval benchmark.
8. Specify typed capability parity for each provider rather than merely listing model names. Include account-level quotas, retry-after handling, circuit state, privacy restrictions, actual tool support, and pre/post-first-token failure behavior.
9. Qualify UUIDv7 guidance: time ordering improves locality; it does not guarantee zero B-tree fragmentation. Preserve Supabase Auth-owned user IDs and intentional natural/composite keys instead of forcing UUIDv7 onto external identities or the `(user_id,date)` usage key.
10. Track “implemented,” “offline tested,” “database integrated,” “staging verified,” and “deferred” independently. Next/Python/model upgrades and the explicit production deferral should be reconciled across canonical docs through recorded decisions, not classified automatically as bugs.

**Recommended execution order**

First close metadata authorization, profile grants/RLS, privileged RPC access, and JWT cache validation. Then repair the lint gate and add disposable-database verification so these controls remain enforced. Next fix native Google tools and capability-correct fallbacks, align deployment/privacy settings, and repair ingestion requeue/retry/idempotency. Finally reconcile contracts/types/docs, complete lifecycle work, and collect staging evidence. Do not advance phases using current green checks as blanket proof of security or architectural completion.

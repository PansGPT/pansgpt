- At 100%, fit each page to the available reading pane with 8px side gutters, including after the desktop chat is opened/resized. Mobile paper has 16px corners and wider pages. Its icon-only Snip/Chat and number-only page counter bar is docked to the bottom and side edges, 60px tall plus the bottom safe area, with rounded top corners only. Hide the mobile progress line. Page opens navigation and reading controls. The mobile header has Help in place of Chat, opening the legacy three-step GIF guide. There is no options control or Help action in the bottom bar.
- Help adapts the legacy `StudyModeTutorial.tsx`: full-width GIF showcase, close overlay, Study Mode Guide label, step title/description, dots and Back/Next/Get started controls. Copy the original AI Chat, Snip and Highlight GIFs into `public/reader-guide`; byte equality with the legacy assets is verified, with no runtime import from the sibling. Animations can be paused and are opt-in with reduced motion.
- Night mode uses a dark surround and original PDF pixels, preserving diagrams and photos. It does not recolor white PDF paper. Sepia remains available.
- Reuse `ChatComposer` for the reader's input, microphone, uploads and study actions. Remove the document-only badge and clinical-facts footer. Snipping remains on the reader toolbar and is absent from the upload menu.
- Home and study share `MobileChatSheet`, `MobileChatHeader`, `MobileChatHistoryList`, sheet CSS and `useSheetSwipe`. Existing conversations use the same New chat / three-dot controls (`ChatHeader` sheet variant); the empty new-chat screen has no right-hand action group or second header. Desktop history shares `ConversationHistoryRow` with the main sidebar, including pinned groups, compact title rows and menus. Collapsed-sidebar CSS applies only inside the sidebar, so it cannot hide reader history. Preserve the rounded top, handle, scrim, history swipe, swipe-to-dismiss, keyboard viewport sizing, focus return and reduced-motion behavior. Reader conversations remain document-scoped; runtime state lives outside the sheet portal so closing/reopening keeps the draft and attachments. Closing cancels active generation as on Home.
- Study history uses the current owner's unarchived, undeleted sessions for the accessible document. Search matches titles and visible selected user/assistant message content. New chat starts a new bound session lazily when a file is submitted or a message is sent. Choosing another conversation clears the draft; toggling history preserves it. Archiving/deleting the selected chat resets to a new chat.

## Supporting materials contract

The user explicitly approved supporting uploads in study chat. The existing owned attachment route now accepts PDF, PPTX, DOCX, UTF-8 text/Markdown/CSV and PNG/JPEG in bound conversations. The open PDF remains the only catalog retrieval/tool target; uploaded files supplement it. Another document ID cannot replace it, and web fallback remains disabled.

- Existing limits: four files per question, 10 MB per file, 40,000 extracted characters per document and 50,000 combined. PDF/PPTX have at most 50 pages/slides. Text extraction includes PDF page and deck slide numbers. DOCX extracts paragraph/table text. Legacy binary DOC/PPT and image-only documents require a supported export or page images.
- Office ZIPs are bounded to 1,000 entries / 20 MiB expanded; reject duplicate/encrypted entries, oversized XML parts, DTD/entities and external/invalid slide references. Parse documents in a subprocess with a 12-second worker timeout, 20-second total timeout and two concurrent slots. Failures do not become fake attachment text.
- Upload never invokes a provider. On Send, owned images are analysed against the question through FastAPI. Bound image questions now also retrieve the open PDF, so both evidence sources reach generation. Store extraction/observations in the saved conversation for follow-up context.
- Add `source_type: "attachment"` and `attachment_id` to the shared/Pydantic citation contract. Streamed and saved source lists label supporting files `Upload: <actual filename>`, separate from page-linked PDF sources. The prompt requires filename/page/slide attribution and disclosure of conflicts; model attribution accuracy still needs provider verification.
- Source identity is server-owned: generic image uploads cannot create a snip marker; server-rendered snips retain their original PDF/page identity. Owner/session/university checks, quotas, private storage and backend-only inference remain enforced at upload, Send and regeneration. No migration, legacy-record import or bucket-policy change.

`GET /api/v1/library/catalog/{id}/conversations?offset=0&limit=30&q=optional` returns `ReaderConversationsResponse`. Search is 2–200 characters. Results recheck document access, filter the owner/document before search, exclude hidden branches and private reasoning, paginate and use private/no-store responses.

## Later composer and guide fixes

- Center the notice icon, copy and close button vertically. Upload failures render through the shared notice area above the composer, rather than inside a 64px image tile. Keep explicit upload retry and preserve the file/draft; dismissing the notice retains recovery actions.
- Apply one guarded file-adder to normal/study pickers, editing, clipboard files and drop. Reserve space while additions finish; reject batches or additions exceeding four before any upload. Staged snips check the same count. The backend's existing per-question limit remains authoritative.
- **Ask AI** sends the owned PDF crop immediately with “Can you explain this snippet for me?” after consent/readiness. Upload through the same backend snip endpoint and send only that crop, without consuming or changing an unfinished draft or other pending files. Stop, chat close and unmount abort pending crop upload; no late stream or automatic POST retry. Upload failures show controlled copy above the input and retain the local image if space remains.
- **Add to chat input** adds only the image, without adding prompt text or sending. Keep existing text unchanged.
- Add Help beside desktop footer reading controls. Open the legacy GIF guide automatically before revealing the PDF on the first visit. Remember that it was shown using an account-specific browser preference across all documents; subsequent visits open it only through Help. Storage failure falls back to session memory. This is browser-local, so clearing storage or using a new browser/device may show it again. Guide text now explains the two corrected snip actions.

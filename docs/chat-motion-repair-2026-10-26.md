# Chat motion repair

User report on `http://localhost:3000/app/chat`: the loader uses the wrong pattern, only the existing Steps UI appears, and text arrives without a streaming reveal. The user selected the **second, scattered twinkle** pattern from the live transitions.dev demo.

Reproduced gap: the previous synthetic preview omitted React Strict Mode, which the real Next configuration enables. More importantly, its motion checks held the stream open between manually injected frames. A new test observes actual CSS transition events and reproduces zero text transitions when `text_chunk` and `done` arrive in the same read, as the real route-or-answer path does. Existing tests checked classes/final rendering rather than a visible transition.

Repair scope: keep the original recipe CSS and semantic palette; use the upstream twinkle delay table and 14px geometry. Separate the live model-authored status from the optional, initially closed activity disclosure. Publish an available writing-status label when generation starts instead of waiting for the first answer token. Track the active backend phase separately from deduplicated activity history. Keep raw reasoning private and introduce no cosmetic inference.

Client presentation contract: add an optional, memory-only arrival timestamp to newly received assistant text. History parsing never populates it. A fresh reply may reveal even when its network batch already contains completion; loaded history remains immediate. Reveal scheduling must survive effect cleanup, honor reduced motion, avoid artificial long queues and leave code/math/link/copy behavior intact.

Exact-prompt routing diagnosis: a privacy-gated routing-only probe of the user's public household-surfactants essay request returned `general_assistance/fast_path`, a 185-word buffered direct answer and no public labels. Add an internal semantic `response_mode` (`brief` / `extended`) so substantial requested writing uses streamed generation without implying course retrieval, web lookup or tools. Enforce a bounded direct-answer budget as a protocol guard; do not add keyword/phrase routing. Model-authored labels still come from the existing decision, and simple responses keep their single-completion path.

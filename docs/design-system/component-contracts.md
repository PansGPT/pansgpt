# Component contracts

`VideoPlayer` requires a real media `src` and accessible `label`; native media events drive playback, time, duration, buffering, volume, mute, rate and captions. Scoped keyboard shortcuts, fullscreen, supported AirPlay and failure announcements are included. Media callbacks compose with caller callbacks; local preview files are released on replacement. `VideoPlayerSurface` and controlled video primitives expose all 62 source specimens at `/?section=video`. Source posters and original glyphs are separate from live media. Live timestamps remain unwrapped and remaining time is computed from actual duration; source elapsed/remaining labels contain inconsistencies.

`ActivityFeed` renders ordered, caller-owned entries with line, connector or no dividers and an explicit empty state. `FeedItem` supplies size, actor/time, avatar, description, optional attachment/labels/message, unread state and a caller-owned read callback. `FeedAttachment` uses a real link or caller open action. Source connectors retain native SVG dimensions; live connectors follow actual content height. Shared avatars now support offline status, and shared file glyphs support TXT/JPG. Six complete feeds with 90 entries and all 16 base variants are at `/?section=feeds`.

`MetricItem` provides nine styles across desktop/mobile and optional footers (36 source frames), caller-owned values, trend content, menu and report actions. `MetricChange` provides six trend/style combinations. `MiniChart` retains all 24 original layer sets with independent background/marker visibility; `MetricChartReference` preserves four native full-width chart exports. Use `Sparkline` with real numeric data for changing values rather than treating source artwork as data. Live chart geometry handles non-finite values, constant series and extreme finite values. Source fixtures and interactions are at `/?section=metrics`.

`CommandBar` supports controlled or internal queries and active IDs, accent-insensitive filtering, grouped results, disabled items, keyboard navigation and caller-owned actions/detail content. `CommandDialog` adds modal focus handling, Escape, focus restoration and optional Meta/Ctrl+K opening. Set `enableShortcut={false}` for additional dialogs. Reusable command rows, inputs, shortcuts, headers, sections, footers and navigation keys preserve the original assets. Ten panels, forty-eight row states and shared primitive references are at `/?section=commands`.

`InlineCTA` supplies seven surface types and automatic or explicit breakpoints. Titles, images, body content and actions remain caller-owned. `InlineCTAActions` reorders primary/secondary actions visually on mobile without duplicating state. `InlineCTAEmailCapture` uses a native required email field, controlled/internal values and a required subscription callback; `pending`, `disabled` and `error` are caller-owned. Plan, feature, payment-method and receipt helpers compose independently. Prices, payment data, downloads, subscriptions and dismissal are never inferred. All fourteen source layouts are at `/?section=inlinectas`.

Import components from `@pansgpt/ui` and import `@pansgpt/ui/styles.css` once. The isolated preview demonstrates these contracts; product integration still follows the staging gate in `docs/build_roadmap.md`.

`open` makes alert, notification and tooltip visibility controlled. Update the supplied value from `onOpenChange`; otherwise use `defaultOpen`. Responsive `breakpoint="auto"` keeps the same component state as the viewport changes. Explicit desktop/mobile values are available for source reference fixtures.

Upload callbacks return actual browser `File` objects. Store those objects in the caller before calling the backend transport. The picker resets after selection, so it is not a persistent native form file field. Queue state, byte progress, cancellation and retry work belong to the caller; no storage or ingestion request is performed by these shared controls. The image-size hint copied from Figma is display text. Validation enforces only the configured file types and byte limit.

Use `progressLabel` on upload rows only when supplied data needs a different display string from the numeric progress value. The archived bar-queue references show 40% and 80% labels with measured 40.29% and 80.58% fills. Production progress otherwise follows its numeric value.

Original SVGs keep their intrinsic sizes and source colors. Icon rotation is applied to tooltip wrapper layers as in Figma. The workbench uses measured tooltip content widths and decorative cursor assets to reproduce source frames; production help icons use real pointer/keyboard behavior.

Source-fixture coverage does not establish every production state, theme or integration as complete. The family ledger remains the record of outstanding work. Notification/alert actions are supplied callbacks; notification imagery and avatar data remain caller-configurable.

The user chose a consistent percentage scale for live circular progress. The larger Figma half-circle examples label an 80%-filled arc as 40%; the source reference gallery preserves those original assets, while `ProgressCircle` interprets 40% as 40% of either full or half arc. `ProgressCircleReference` is fixed artwork, not an interactive progress input.

Dot-spinner SVG exports contain embedded HTML conic gradients that render blank in browser image contexts. Four PNGs were exported directly from the original Figma graphic nodes at native scale; the original SVGs and export provenance remain archived. Static source artwork retains source colors across themes.

`Slider` defaults to no visible value label. Use `labelPosition="bottom"` or `"top-floating"`, and `formatValue` when the range is not a percentage. Source reference compositions preserve Figma's anomalous final unlabeled 75–100% range, which extends 8 px beyond its frame; live range data follows Radix's bounds.

Verification-code cells are presentation layers around one native text input. `onComplete` reports a newly completed numeric code; it does not verify it or submit a request. The caller owns verification, expiration, errors and controlled resets. Labels and errors connect to the native input. Set `responsive={false}` only for fixed-size source inspection; production defaults shrink within the available width. Empty cells display a decorative zero but submit an empty value.

Profile verification defaults to false and reflects caller-owned data. An unavailable profile image switches to the original placeholder geometry; replacing its URL recovers the portrait. Avatar image cards omit their caption when neither caption nor source is supplied. Figma's Source text has no hyperlink, so no photographer/provenance URL is inferred.

App-store badges without href expose an accessible image and do not create a dead link. Supply a real product listing to enable native navigation. Social group callbacks report the selected platform; authentication, session state and backend requests belong to the application. Static reference states and decorative source cursors are for source inspection.

Tab selection uses Radix panels. `fullWidth` distributes the supplied items; it does not truncate the list. For a React-node tab label, supply `mobileLabel` when its accessible mobile text differs from the item value. Standalone `TabButton` exposes `aria-pressed`; inside Radix tabs, `aria-selected` carries selection semantics.

Carousel indices start at zero and are clamped to the current slide list. Looping defaults to true; `loop={false}` disables boundary arrows. The caller supplies image content and alt text. There is no automatic rotation or background fetch.

Progress steps are informational by default. Passing `onValueChange` or `interactive` enables native actions; a controlled `value` stays caller-owned. Explicit item statuses override the derived complete/current/upcoming sequence. Counters can be hidden. Source fixtures preserve Figma's fixed numeral/text frames and the one-pixel mobile width anomaly; live layouts use available width. Current-ring and live-connector PNGs are direct native graphic exports, not screenshots or redrawn artwork.

`EmptyState` takes caller-supplied title, supporting text and optional primary/secondary actions. An action requires its callback; the component does not infer navigation or data mutations. The four treatments are featured icon, illustration, file and folder, in three sizes. Graphics and decorative patterns can be hidden. `Illustration` provides cloud, box, documents and credit-card artwork in all three sizes; it is decorative unless given a label. Original SVGs retain their intrinsic dimensions. The folder and its decorative grid use original native PNG exports to retain the source noise/mask effects. Source fixtures preserve Figma's fixed action widths; live actions fit their labels.

`CodeSnippet` accepts plain text or caller-formatted lines and never interprets the source as HTML. Tabbed examples support controlled or internal selection, disabled tabs, optional expansion and clipboard copying of the full selected code. Clipboard failure is reported through `onCopyError` and an accessible status message. Syntax coloring and product-specific code parsing remain caller-owned. The original Roboto Mono variable font and license are included locally.

## Section labels, headers and footers

`SectionLabel` supplies small/medium typography, optional supporting text, required indicator, shared help tooltip and caller-supplied action slots. Set `htmlFor` to the native input ID; set `supportingTextId` and reference it through the input's `aria-describedby`. Input validation belongs to the input. Four Figma source layouts are available at `/?section=sectionlabels`.

`SectionHeader` accepts title/supporting content, optional leading content and badge, action/control/menu/tab slots, and automatic or explicit desktop/mobile layout. `mobileActions` defaults to the desktop actions; provide the intended subset when the source uses fewer mobile actions. Compose shared Button, ButtonGroup, Dropdown and Tabs controls. `SectionHeaderSearch` keeps its query caller-owned and focuses with Meta/Ctrl+K when enabled. Set `enableShortcut={false}` for additional search fields so only the intended primary search handles the shortcut. Twelve source layouts are available at `/?section=sectionheaders`.

`CardHeader` composes the same header behavior with source card padding, optional caller-supplied avatar, badge, and native card divider. Its four source layouts are available at `/?section=cardheaders`. Menus remain caller-supplied so actions and authorization stay with the application.

`SectionFooter` accepts section/card spacing, control/mobile-control, secondary-action and action slots. Responsive controls must share the same caller-owned selection value. The original mobile source is 688 px wide; the live layout wraps actions below the controls at narrower widths. Eight source layouts are available at `/?section=sectionfooters`.
`PageHeader` implements six styles across desktop/mobile layouts: simple, avatar, banner simple/avatar, and both centered banner styles. Navigation, back link, avatars, actions, search and custom banner content remain caller-owned. Supply appropriately sized `avatar`/`mobileAvatar` nodes and the intended `mobileActions` subset; keep their values shared. Twelve source layouts and responsive search/navigation checks are at `/?section=pageheaders`.

`TextEditor` uses native browser editing with trusted React `initialContent` or a plain `defaultValue`. It emits text/HTML snapshots and preserves native selection and undo. Reset through React `key`; HTML snapshots are output and must not be passed into an unsafe HTML renderer. Pasted content is inserted as plain text. `maxLength` limits native typing, paste and returned text insertions. Formatting uses native editing commands, including browser-supported undo; size selection applies the exact source pixel size. `disabled` and `readOnly` prevent edits and toolbar actions. Product callers own link/media/generation requests through `onRequest`; generation must call the existing FastAPI backend. Unsupported external actions are disabled without a request callback. Errors can be surfaced through `onRequestError`.

`TextEditorToolbar`, `TextEditorTooltip`, `TextEditorIcon` and `EditorColorSelect` also compose independently. Arrow/Home/End keys move between toolbar buttons. The six editor families include four size/toolbar layouts, forty-eight icon states, two color-selection states, two toolbar layouts, two floating toolbar layouts and the source highlight specimen. `TextHighlight` marks live content; `TextHighlightReference` retains the 400×24 source highlight and optional formatting toolbar. `ScrollbarReference` is a decorative source specimen; live editor scrolling remains native. Source-only decorative scrollbar specimens are enabled with `referenceScrollBar`. The isolated editor workbench is `/?section=editors`.

# Messaging

`Message` composes actor, timestamp, received avatar, delivery state, reactions and caller-owned actions. The 33 source variants cover text, replies, writing, files, audio, images, video and both link previews. `MessageReaction` is controlled; `MessageStatusIcon` exposes readable delivery state and focus/hover tooltips. Action panels follow the source bottom placement, with image actions above the caption. Original file-type labels and unscaled SVG roots remain intact.

`MessageComposer` supports minimal, textarea and advanced layouts, controlled or internal drafts, Enter to send, Shift+Enter for a newline, IME composition, pending/disabled state and asynchronous failures. It trims empty submissions, prevents concurrent sends, retains failed drafts and preserves edits made during a request. Context, recording, attachments, shortcuts and sending are caller-owned callbacks; inference must route through FastAPI.

`AudioPlayer` uses native media events for playback, duration, seeking and errors. `AudioPlaybackReference` preserves Figma's original waveform at its intrinsic size inside a clipped slot; it is explicitly a source specimen and does not represent measured live audio. The production player displays actual playback progress.

## Native fields and selectable cards

`Input` supports leading icon/text/dropdown, trailing dropdown/button, payment and wrapping tag layouts. Country/currency selectors retain native submission behavior. `Combobox` uses a searchable listbox with single or multiple selected values; callers own option data and `onValueChange`. Disabled options cannot be selected or removed. `TagInput` and `TagTextarea` commit unique labels on Enter/comma, submit committed values and permit accessible dismissal; no transport or backend mutations are inferred.

`Radio` is a native single-choice input: give related choices the same `name`. `SelectionCard` adds radio, checkbox, icon, pricing, avatar and payment content. Standalone checkbox cards permit multiple values; `SelectionCardGroup` is a single-choice radio group in any of the six visual templates. Card actions remain independent controls and disabled actions are removed from keyboard interaction. Required, disabled, caller-controlled values and native form submission are preserved. Original glyphs can be supplied through the icon/check slots. Selection-card source examples use explicit breakpoint values; product content responds to the actual viewport.

`Calendar` exposes caller-owned highlighted dates and disables navigation outside years 0001–9999. Date presets omit ranges that cannot be represented at the first supported year. The source matrices are available at `fields`, `controls`, `tags` and `radios` in the isolated workbench.
